# Voice Security — Phase 1 (AASIST-L Working Baseline + Accuracy)

Phase 1 goal: get the pretrained AASIST-L ONNX model running reliably,
build a solid inference pipeline around it (preprocessing, segmentation,
aggregation, decision thresholding), and measure baseline performance —
**before** deciding whether fine-tuning is actually needed.

No quantization, FP16, mobile optimization, or TensorRT in this phase.

## Project structure

```
voice-security/
├── models/
│   └── aasist-l.onnx          ← place the pretrained model here (not included)
├── src/
│   ├── audio_preprocessing.py ← load, mono, resample, normalize
│   ├── segment_audio.py       ← split waveform into windows
│   ├── aasist_onnx.py         ← ONNX Runtime wrapper around the model
│   ├── inference.py           ← full pipeline: audio -> score -> decision
│   ├── aggregation.py         ← mean / median / weighted / top-k / vote
│   ├── decision.py            ← score -> REAL / SPOOF / UNCERTAIN
│   └── evaluate.py            ← batch evaluation + metrics (incl. EER)
├── test_audio/
│   ├── real/                  ← put labeled real recordings here
│   └── spoof/                 ← put labeled spoofed recordings here
├── results/
│   ├── predictions.csv        ← generated by evaluate.py
│   └── metrics.json           ← generated by evaluate.py
├── tests/
│   ├── test_model.py          ← Step 2: verify ONNX input/output shapes
│   └── test_audio.py          ← preprocessing/segmentation unit tests
├── main.py                    ← CLI entry point
├── config.py                  ← all tunable parameters live here
└── requirements.txt
```

## Setup

1. **Create and activate a virtual environment**

   ```bash
   cd voice-security
   python3 -m venv venv
   source venv/bin/activate        # Windows: venv\Scripts\activate
   ```

2. **Install dependencies**

   ```bash
   pip install -r requirements.txt
   ```

3. **Add the model**

   Download the pretrained AASIST-L ONNX export and place it at:

   ```
   models/aasist-l.onnx
   ```

   You do **not** need `AASIST-L.pth`, `_net.py`, `aasist_l.py`, or
   `trt_aasist_l.py` for Phase 1 — those are only needed if fine-tuning
   the original architecture becomes necessary later.

## Step-by-step usage (matches the Phase 1 plan)

### Step 2 — Verify the ONNX model

Never guess the input format. Inspect it first:

```bash
python main.py inspect-model
```

This prints the model's real input/output name, shape, and dtype. Compare
this against `config.TARGET_SAMPLE_RATE` and `config.SEGMENT_LENGTH_SECONDS`
and adjust `config.py` if they don't match.

### Step 1/3/4 — Run inference on a single file

```bash
python main.py analyze test_audio/real/real_001.wav
```

Prints per-segment scores, the aggregated score, and the final decision.

### Step 6/7 — Build the evaluation dataset and run batch evaluation

Populate:

```
test_audio/real/    — genuine recordings (vary speaker, mic, environment)
test_audio/spoof/   — spoofed recordings (vary TTS/VC method, compression, noise)
```

Then run:

```bash
python main.py evaluate
```

This writes:
- `results/predictions.csv` — per-file scores, decisions, inference time
- `results/metrics.json` — accuracy, precision, recall, F1, EER, FPR, FNR

### Step 5 — Experiment with the pipeline

All of the following are config-driven, so you can sweep them without
touching pipeline code:

- `config.AGGREGATION_STRATEGY` — `"mean"`, `"median"`, `"weighted_mean"`,
  `"top_k"`, `"majority_vote"`
- `config.SEGMENT_LENGTH_SECONDS` / `config.SEGMENT_OVERLAP_SECONDS` —
  single window vs. multiple windows vs. sliding windows
- `config.SPOOF_THRESHOLD` / `config.UNCERTAIN_MARGIN` — decision boundary,
  to be set from validation data rather than assumed at 0.5

Re-run `python main.py evaluate` after each change and compare
`results/metrics.json` across runs to see what actually improved things.

### Running tests

```bash
pytest tests/ -v
```

`tests/test_model.py` requires `models/aasist-l.onnx` to be present; it
skips automatically otherwise. `tests/test_audio.py` uses synthetic audio
and runs regardless.

## Decision point: fine-tuning

Once the baseline metrics in `results/metrics.json` are in hand:

- **Good enough** → keep the pretrained model + tuned inference pipeline.
- **Not good enough** → that's the evidence needed to justify collecting
  more training data and fine-tuning AASIST-L — a Phase 2 concern, not
  Phase 1.
